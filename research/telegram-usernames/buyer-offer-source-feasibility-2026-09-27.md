# Exact-NFT buyer-offer source feasibility (2026-09-27)

Research-only, read-only probe. No offer amount was used as a quote, feature or portfolio value. No paid access, production worker or deployment was changed.

The [Getgems contract catalog](https://github.com/getgems-io/nft-contracts) publishes the `nft-offer-v1r3.fc` code hash (`bl1mf6bvqBh8bQKe/UAVYBIy/S42wpHbw0be2rbcgCQ=`) and a mainnet example offer contract (`EQAPCdspv0uVHTa3ItpR49FlBEaaBKFDz5G8m6fmEyqhyY3J`). The [TON Center v3 action API](https://docs.ton.org/api/v3/actions-and-traces/get-actions) allows filtering by account, action type and time, but its documented query parameters do not include NFT identity or contract code hash. The live [OpenAPI schema](https://toncenter.com/api/v3/doc.json) likewise lists only `address,include_boc` for `/accountStates`, account/time/hash filters for `/transactions`, and no code-hash or NFT-identity filter for `/actions`; `/nft/sales` accepts an address and is not an offer-discovery endpoint.

A bounded unauthenticated `/actions?account=<published offer>&action_type=contract_deploy&include_transactions=true&limit=10` call returned the example deployment. Its transaction's resulting code hash matched the published Getgems offer hash. The deployment action exposed a source wallet and destination offer-contract address, but no exact NFT identity. [TonAPI account data](https://docs.tonconsole.com/tonapi/rest-api/accounts) identified the deployment source as `wallet_v3r2`, not a shared offer factory; scanning one common deployer therefore does not discover all offers. The known offer's account-scoped action history contained generic `contract_deploy`, `ton_transfer` and `nft_transfer` actions, not an indexed exact-NFT offer record.

Three small global TON Center `/actions` probes around the example's deployment time (`1712231820`) returned HTTP 500: a 120-second `contract_deploy` filter at limits 100 and 10, and a two-second unfiltered query at limit 10. This is an observed failure for those requests, not proof global scanning is impossible under every configuration. A general scan of all deployments to find matching code hashes is therefore not a verified practical wallet-time retrieval path on the current public endpoint.

The earlier unauthenticated [Getgems exact-NFT offer endpoint](https://api.getgems.io/public-api/docs) returned HTTP 401. The contract source plus the example deployment prove an on-chain offer primitive exists, but do not prove current Username-collection coverage, active funding, exact-NFT retrieval, expiry status, or historical predictive value. Do not convert listings, generic transfers, stale offers or this example into buyer-demand prices. Revisit only if a permitted indexed exact-NFT source or a bounded, verifiable self-indexing route becomes available; then independently check collection/NFT identity, offer contract version, live balance, expiry/completion and point-in-time availability before testing any estimator feature.
