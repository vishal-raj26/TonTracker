# TonTrack presentation rebuild

Status: in progress, not a completion certificate. October 4, 2026.

Authority: the original Fomo brief plus the user's ground-up course correction. Current APIs, data and behavior define product capabilities, not layout. On the subsequent turn the user confirmed the existing actual-device inspection is sufficient to proceed. Reopen Fomo only for a specific unresolved decision; do not pretend a fresh inspection occurred.

## Product roles, independent of legacy layout

- Home answers: what do I own, what is it worth, and where can I open it? Priority is current portfolio value, ownership/category access, notable holdings, recorded history, recent events. It must work without history on day one.
- Assets is the full browsing/search/filtering workspace, including all nested collectible collection/model/item levels. Domain identity and evidence remain specific to each asset type.
- Analytics answers exposure and performance questions, not inventory navigation. One allocation visualization and one verified token mover representation replace competing copies.
- Detail answers what this asset is, the available price basis, its history and supporting evidence. Secondary metadata belongs behind contextual sections; deep back navigation must preserve the originating collection/filter/scroll.
- Activity is the chronological investigation workspace. Overview is a short entry point, not a duplicate full activity view.
- Watchlist and Settings remain accessible; no social or trading functionality is imported from Fomo.

## Shared composition foundation

Use the centralized product tokens in styles-product-system.css: unboxed financial values/lists, neutral surfaces reserved for meaningful bundles and controls, a deliberate spacing scale, 44px minimum controls, consistent metadata/value typography, tabular numbers, quiet icons, explicit unavailable states and focus feedback. The existing font/color may remain when justified: structural change must still be evident if typography and color are held identical. Do not add ornamental surfaces to simulate a redesign.

Home has a separate value overview and six-category native-button browser. Counts derive from actual owned assets; values reuse accepted portfolio totals, never new estimates. Moving holdings preserve unique items and original routes; recorded history comes later and is never substituted for the current total. Analytics owns the interactive allocation and token movers. The first viewport no longer starts with a history dashboard.

## Preservation boundaries

Do not alter backend valuation/import contracts merely to fit the new presentation. Gift identity remains collection/model/backdrop; pricing gates and registered media remain intact. DNS low-confidence/indicative exclusion and unavailable semantics remain canonical. Saved wallet switching must clear the new inventory widgets too. No new request per category or carousel frame.

Keep chart data-integrity, cache, keyboard/modal, import isolation and pricing tests. Replace tests that assert old section ordering with tests of the new composition and retained capabilities; green legacy CSS-string tests do not prove product quality.

## Unfinished gates

Then rebuild Assets and every nested collectible/token/identity detail from purpose, followed by remaining navigation/utility experiences and global states. Consolidate legacy CSS after each new scaffold is verified; do not regard the current bridge cascade as final architecture. Consult FOMO_REDESIGN_COVERAGE.md for the exhaustive route/state backlog. The whole-app goal remains incomplete.
